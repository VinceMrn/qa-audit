Findings

Warning

No landmarks — 8 of 10 nodes sit outside any region

The page has a single <div id="root"> and no <main>, <header> or <nav>. Screen-reader users navigate by landmark before they read anything, so a page without them offers no way in other than reading top to bottom. Two axe rules fire on this: region for the orphaned content and landmark-one-main for the missing main.

axe-core 4.10.2
  [moderate] region              8 nodes   All page content should be contained by landmarks
  [moderate] landmark-one-main   1 node    Document should have one main landmark

qa.outline()
  headings   : h1 "Get started", h2 "Documentation", h2 "Connect with us"
  landmarks  : []            ← none at all

Suggested fix — Wrap the app body in <main>. On this template that is a one-line change in App.jsx and it clears both rules at once.

Warning

The counter button sits at 3.82:1

The default purple-on-lilac counter button falls below the 4.5:1 AA floor for body-sized text. Worth noting that the two engines disagree slightly — axe resolves the button's own light background and reports 3.82:1, while qa.contrast walks up to the white body and reports 4.39:1. axe is right here; on a flat background it is the more accurate of the two, which is exactly why both are run.

axe-core     : 3.82:1  foreground #aa3bff on background #f7ebff, 16px
qa.contrast  : 4.39:1  (resolved the body white, not the button's own background)
AA floor     : 4.5:1   for text under 24px

Suggested fix — Darken the label or the surface. #8b1fd6 on the same lilac clears 4.5:1 while keeping the palette.

Info

The preview server sets no security headers

vite preview serves without Content-Security-Policy, X-Content-Type-Options or Referrer-Policy. This is expected — it is a local preview, not a deployment target — and is listed only as a reminder that these come from your host or CDN, and are worth checking on the deployed site where they actually apply.

headers.js
  missing: contentSecurityPolicy, xContentTypeOptions,
           xFrameOptions, referrerPolicy, permissionsPolicy
  caching     : all static assets fingerprinted and cached  ✓
  compression : no uncompressed textual responses           ✓

Suggested fix — Nothing to change locally. Verify the headers on the deployed site, where the CDN or reverse proxy sets them.
